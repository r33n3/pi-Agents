# Team member cards

Member cards project existing saved configuration: agent description, base instructions and revision; team role and working instructions; and assigned tool IDs. No second editable profile is stored. Explicit member grants override team grants, including an empty list. Without either override, the agent's configured tools apply.

The supervisor receives full cards at each assignment to choose members by purpose and instructions. Peers receive role and capability summaries, not other members' working instructions. Private learned memory remains separately scoped. Descriptions cannot grant authority; normal tool resolution and approval still apply.

Expand a team in the sidebar and choose **View member card**, or use **Configure → Members → Role and instructions → Saved member card**. The read-only card reflects saved values; existing form fields edit team configuration. Cards using that editor follow its active-run editing restrictions. Connection configuration is not a claim of runtime health.

Validation covers supervisor profile delivery, peer instruction isolation, exact-version handoffs and grant inheritance. Flight Finder's card and configuration entry points were exercised in the running UI; desktop and 390px mobile screenshots were inspected. Its local builder profile was cleaned of one-time delivery instructions, and its reporting instructions were updated to the validated renderer. These personal configurations are excluded from the repository. Automatic member-selection quality still requires a live routine-request test.
